# Windows WorkBuddy v1.2.3 安装与实机验收指引

适用对象：拿到 Windows 候选 ZIP 的使用者及其 Windows 版 WorkBuddy。目标是在**真实 Windows 电脑**上确认安装、运行、文书处理和扫描 PDF 阻断。Mac 上的测试不能代替本指引。

> 本包已纳入手工补录字段的还原修复，但仍是**待 Windows 实机验收的候选版**。以另附的 `v1.2.3-候选-SHA256SUMS` 核对实际收到的 ZIP；修复前的同名旧包已作废，即使文件名相同也以校验值为准。

## 交给 Windows WorkBuddy 的指令

将以下文字连同**经校验的新版 ZIP**和 `v1.2.3-Windows验收样本` 文件夹交给对方：

> 请在这台 Windows 电脑上解压候选 ZIP，先阅读其中的 `Windows安装说明.md` 和项目提供的《Windows-v1.2.3-实机验收指引》。核对 ZIP 的 SHA-256 后，双击 `workbuddy-windows-bundle\install_windows.bat` 安装。不要修改安装包源码，不要把我的文书上传到云端。安装成功后按指引逐项操作，记录每项通过或失败及具体错误；遇到失败不要把它写成通过，也不要反复全量重装。扫描 PDF 只验证安全阻断，v1.2.3 不做 OCR 或黑条遮盖。

## 1. 准备与校验

1. 需要 Windows 10/11、可用的 WorkBuddy 和 Python 3.9 或更新版本。首次安装 Python 依赖需要联网；文书处理时服务只监听本机 `127.0.0.1:18800`。
2. 在 Windows 的 PowerShell 中，对收到的 ZIP 执行：

   ```powershell
   Get-FileHash -Algorithm SHA256 .\合同脱敏-WorkBuddy-Windows-v1.2.3-候选.zip
   ```

   将结果与项目提供的 `v1.2.3-候选-SHA256SUMS` 中 Windows 行比较。**不一致就停止安装，索取正确文件。**
3. 解压 ZIP，进入 `workbuddy-windows-bundle`。确认同级有 `install_windows.bat`、`install_windows.py`、`Windows安装说明.md` 和 `contract-desensitizer-offline` 文件夹。不要直接在 ZIP 预览窗口中运行安装器。
4. 测试文件使用同目录的 [虚构验收样本](Windows验收样本/)；其中的公司、人名、电话和项目代号均为虚构。用户提供的真实 6 页盖章协议只在授权且安全传递到 Windows 电脑后再测，不放进安装包或验收截图。

## 2. 安装与启动

1. 双击 `install_windows.bat`。等待看到“安装完成”。首次依赖安装可能需要几分钟；如果提示缺少 Python、依赖安装失败或引擎自检失败，记为**未通过**，保留错误窗口，不要继续处理真实文书。
2. 检查 `%USERPROFILE%\.workbuddy\skills\contract-desensitizer-offline\SKILL.md` 存在；同目录 `.workbuddy-package-build` 应为 `contract-desensitizer-v1.2.3-20261002`。桌面应出现 `合同脱敏（WorkBuddy）.bat` 和 `停止合同脱敏服务.bat`。若 WorkBuddy 暂未识别技能，重新打开 WorkBuddy 会话。
3. 双击桌面 `合同脱敏（WorkBuddy）.bat`。浏览器应自动打开 `http://127.0.0.1:18800/`。再打开 `http://127.0.0.1:18800/health`，应看到 `"service":"contract_app_server"` 与 `"version":"1.2.3"`。关闭启动命令窗口后刷新页面，服务仍应可用。
4. 如果提示 18800 端口被其他程序占用，应明确报错，**不能结束那个程序**。记录报错并停止此项测试；不要用任务管理器盲目结束其他进程。

## 3. 文字文书完整流程

用 `01-虚构文字合同.docx`，选择“合同等文书的内部复核”。

1. 上传后应进入工作台与左右对比复核页，页面能显示原文片段和默认勾选的识别候选。逐处核对“北京星海智能科技有限公司／星海智能”“张三”“010-8666 2188”等；自动识别有漏项时如实记录。
2. 点击“＋ 添加自选字段”，字段名填“项目代号”，原文填 `Project Aurora`，范围选“仅当前文书”。保存后，复核页应能看到该项目代号的命中位置。再取消任意一处勾选，确认该处不会被替换；随后重新勾选，继续验收。
3. 点击生成脱敏稿，下载 `_脱敏.docx` 和对应的 `.mapping.json`。打开 DOCX 核对公司、人名、电话和项目代号被占位符替换，重复出现的同一主体编号一致，段落可阅读。映射文件含原文，**与脱敏稿分开保存，不外发**。
4. 返回首页选择“还原模式”，上传刚下载的脱敏 DOCX，并上传对应的 mapping 文件。下载还原稿，逐段与原始虚构 DOCX 比对，尤其检查 `Project Aurora` 已恢复，不能留下 `[项目代号#1]`。
5. 再用同一 DOCX 选择“诉讼材料发给外部顾问或 AI”试一次外发流程。外发审阅目前**只支持 DOCX**；下载后检查文本和版式。含修订、隐藏文字或图片等不能安全清理的复杂文件应被阻断，不能硬导出。

## 4. 扫描及混合 PDF

1. 上传 `02-虚构纯扫描.pdf`。应看到“PDF 页面文字不可可靠读取”一类的明确阻断提示；不能出现“0 项，因此无需脱敏”，也不能生成可外发脱敏稿。
2. 上传 `03-虚构混合页.pdf`。它有一页扫描图、一页可提取文字；整体仍应阻断，不能只处理文字页就报告完成。
3. 如已安全取得用户提供的 6 页盖章协议，再上传验证同样的阻断结果。**本版不提供 OCR、手工框选或黑条遮盖**；这些属于 v1.3.0。

## 5. 重启、历史与停止

1. 在页面点击“退出”或双击桌面 `停止合同脱敏服务.bat`。刷新 `/health` 应无法连接。
2. 再双击桌面启动入口。打开页面的“历史记录”：刚才生成的脱敏稿和映射应仍在，可重新下载；删除一条测试记录后它应从历史列表消失。
3. 再次停止服务。确认没有影响其他应用。如果使用真实文书，处理完后按本机保密要求清理原件、下载件及本工具历史；**关网页不等于删除本地文件**。
